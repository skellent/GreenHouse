Arquitectura de monitoreo y configuracion

Resumen operativo para entender como la app conversa con el ESP32-S3 y como se organiza la experiencia movil.

GET /api/datos

Devuelve sensores, estado del ESP32 y resultados de IA. La app guarda la respuesta completa en historial y exporta los campos actuales mas `raw_json`.

{
  "sensores": {
    "temperatura_ambiente": 26.1,
    "temperatura_agua": 23.8,
    "humedad_ambiente": 58,
    "humedad_suelo": 41,
    "intensidad_luz": 720,
    "ultrasonido": 18
  },
  "esp32": { "temperatura": 42, "camStatus": true },
  "ia": { "intensidad_uv": 0.72, "riego": true, "ventilacion": false, "perfil": 2 }
}

GET /api/foto

Devuelve una imagen JPEG. La app realiza dos solicitudes consecutivas porque algunos builds del ESP32-S3 entregan un frame cacheado en la primera lectura.

POST /api/perfil

Recibe texto plano `1`, `2` o `3` para seleccionar `Desertico`, `Tropical` o `Alpino`.

POST /api/wifi

Recibe JSON con `red` y `psw`. El ESP32 responde antes de reconectarse para evitar perder la respuesta HTTP.

Aplicacion

Flujo de uso recomendado

1Configurar IP local del ESP32-S3.
2Activar lectura automatica cada 1 o 2 segundos.
3Registrar historial cuando se necesite evidencia de monitoreo.
4Exportar CSV y revisar tendencias de sensores e IA.
